# GEM12 指纹传感器长按对照验证

日期：2026-10-09。

## 结论

本次在同一次 Windows 生物识别事件监听中对照轻触和长按：用户确认完成 3 次轻触和 3 次约 3 秒的长按并放开，实际收到 3 个轻触阶段事件、1 个长按阶段事件。两阶段事件内容相同，没有按下、松开或接触时长字段，监听结束前没有更多通知。

现有 `WINBIO_EVENT_FP_UNCLAIMED` 路径不能可靠实现参考项目的长按判断。3 次长按只收到 1 个事件的原因尚未确定，也不能确认该事件对应哪一次操作，或发生在按住期间还是松开后。不能用相邻事件的间隔推算接触时长。

轻触可继续作为面板切换输入的候选，尚不能保证每次操作严格产生一个事件。这一结论仅针对本机当前驱动和本次 Windows 事件接口，不代表传感器或所有 Windows 接口均不支持接触状态。

## 范围及过程

- 设备：Microarray WBDI，USB `3274:8012`，当前驱动 `9.47.11.214`；没有替换驱动。
- 枚举结果：Unit ID 3、Subtype 2、Capabilities `0x00000007`。
- 测试前 `WbioSrvc` 为 Stopped，启动类型 Automatic。
- 临时 Python ctypes 探针使用系统池和默认配置，注册 `WINBIO_EVENT_FP_UNCLAIMED`。回调只记录设备编号、状态和收到通知的时间，将事件放入队列并释放系统内存。
- 监听就绪后，请用户轻触 3 次，每次放开并间隔约 2 秒；用户确认完成。
- 随后切换至静默阶段，再进入长按阶段；请用户按住约 3 秒后完全放开，放开后间隔约 3 秒，共 3 次；用户确认完成。
- 阶段标签由探针读取控制文件后设置，不是传感器提供的状态。没有同步记录每次实际按下和松开的时间。
- 未调用身份识别、指纹录入、模板读取、原始采样或厂商控制接口，未操作屏幕。

## 实测结果

时间为相对探针启动的秒数，不是触摸响应延迟。

| 阶段 | 阶段开始时间 | 用户确认操作次数 | 实际事件数 |
|---|---:|---:|---:|
| 轻触 | 0.072 秒 | 3 | 3 |
| 静默 | 50.207 秒 | 无操作指令 | 0 |
| 长按 | 81.711 秒 | 3 | 1 |

| 阶段 | 事件时间 | 类型 | Unit ID | HRESULT | RejectDetail |
|---|---:|---|---:|---|---:|
| 轻触 | 27.801 秒 | `0x00000001` | 3 | `0x00000000` | 0 |
| 轻触 | 30.346 秒 | `0x00000001` | 3 | `0x00000000` | 0 |
| 轻触 | 32.997 秒 | `0x00000001` | 3 | `0x00000000` | 0 |
| 长按 | 104.198 秒 | `0x00000001` | 3 | `0x00000000` | 0 |

探针配置约 180 秒监听上限，到期正常退出，原始状态为 `timed_out`；含注销和关闭过程的总运行时间为 190.157 秒。共记录 4 个事件，无错误事件。这个状态表示到达监听时限，不是 API 调用失败。

枚举设备、打开会话、注册监听、注销监听及关闭会话的 HRESULT 均为 `0x00000000`。原始探针结果及用户操作确认、服务恢复信息见[指纹长按验证数据.json](指纹长按验证数据.json)。

## 恢复和后续边界

测试自动启动了 `WbioSrvc`。监听结束后，按用户此前授权经管理员确认仅停止该服务，已核对恢复为 Stopped，启动类型仍为 Automatic。临时探针和控制文件已清理，正式代码未修改，未提交。

若要实现参考项目的长按，需要先找到可用的接触／松开接口或厂商资料，再做对应验证；本次不加入基于事件间隔猜测的长按逻辑。轻触正式接入之前仍需验证连续操作及与 Windows Hello 的共存。
