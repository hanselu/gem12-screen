# 独立指纹轻触接口实现及验收

日期：2026-10-09。

## 实现

新增独立 Python 包 `gem12_touch`，公开 `FingerprintTouch`、`TouchEvent` 和 `TouchError`。屏幕继续使用原有 `gem12_screen`。两个模块没有互相导入，轻触模块仅依赖 Python 标准库和 Windows 自带的 `winbio.dll`。同一发行包包含这两个 Python 包，没有新增运行依赖。

`FingerprintTouch.connect()` 按 USB `3274:8012` 在 Windows 生物识别系统池中寻找目标设备，注册 `WINBIO_EVENT_FP_UNCLAIMED`。通知回调只复制目标设备的事件字段、放入队列并释放系统分配的内存，不运行用户业务。调用方通过 `read(timeout=...)` 依次取出事件；超时返回 `None`，通知错误抛出 `TouchError`。

事件保留 Unit ID、收到通知时的单调时钟时间及 RejectDetail。调用方只应在 RejectDetail 为 0 时将通知作为成功输入。没有自动去重、重试、长按判断、画面切换或硬件数据采集。

`close()` 注销事件后关闭会话，可重复调用；上下文退出和连接失败时会清理。注销失败仍尝试关闭会话，清理失败会明确报错并保留原生回调的引用，避免回调提前被回收。读取和关闭应在同一调用线程顺序执行。

独立示例为 `examples/listen_touch.py`，只打印通知，不连接屏幕。

## 自动验证

`uv run --no-sync python -m unittest discover -s tests -v`：23 项通过，包括原有屏控及协议测试 14 项、新增轻触测试 9 项。

新增测试覆盖注册期间立即收到通知、事件排队顺序及超时、其他设备过滤、采样拒绝信息保留、系统错误传递、事件内存释放、设备选择和注册失败清理、注销失败后继续关闭、清理失败后的回调保留与重试、调用方异常退出以及导入独立性。测试使用模拟 Windows 接口，不访问硬件。

`uv sync` 和 `uv build` 成功。安装包包含两个模块，原有屏幕背景资源保留；从构建出的 wheel 解包后核对可独立导入轻触模块，未加载屏控、串口或 Pillow，并验证原有屏幕模块可导入。最初在沙箱中构建依赖受到 Windows PE 资源写入权限限制，随后在沙箱外完成验证，临时目录配置在项目 `.tmp` 内。

## 真机验收

设备为 Microarray WBDI，Present、Status OK，Unit ID 3。两轮均调用正式的 `FingerprintTouch` 接口，不识别身份、不录入指纹、不读取模板、不替换驱动，也未连接或操作屏幕。

| 轮次 | 用户确认操作 | 模块通知 | 系统回调诊断 | 相对时间（秒） |
|---|---|---:|---|---|
| 第一轮 | 3 次轻触，每次放开 | 2 | 未额外记录原始回调 | 25.016、28.078 |
| 居中复测 | 3 次轻触，每次指腹居中并完全放开 | 3 | 3 次，与模块通知逐条对应 | 35.766、39.813、44.141 |

所有收到的通知 Unit ID 为 3、RejectDetail 为 0。复测的 3 次原始回调均为类型 1、HRESULT `0x00000000`；本轮没有发现系统回调与对外读取之间的通知丢失。临时诊断仅在内存中记录回调进入时间、状态和执行时间，不在回调中写文件。

用户提出第一轮可能有一次手指位置不好。居中复测结果与这个解释相容，但不能证明第一轮少一次的原因，也不能排除其他因素。第一轮没有原始回调诊断，不能追溯判定通知是否在系统上报或模块处理环节缺失。

两轮均成功关闭监听，重复关闭成功，然后重新连接到 Unit ID 3，短暂等待没有额外事件，再成功关闭第二个会话。这验证了基本事件获取及连接清理流程，不是对所有接触、长期运行、Windows Hello 共存或睡眠唤醒的保证。

原始两轮结果、用户操作确认及环境恢复信息见[独立轻触接口验证数据.json](独立轻触接口验证数据.json)。

## 状态恢复与边界

测试前 `WbioSrvc` 为 Stopped、Automatic。Windows 调用生物识别接口自动启动该服务；验收结束后按用户此前授权经管理员确认仅停止该服务，已核对恢复为 Stopped、Automatic。正式接口不会自行停止共享服务。临时脚本、诊断结果副本及构建检查目录已清理，代码尚未提交。

接口的通知是采样事件，不提供按下／松开或接触时长，不保证每次物理接触一定产生一个通知。后续用户日志确认了第 16 次后不再进入回调、关闭会话约 10 秒；进一步诊断修正了在打开会话前固定旧 Unit ID 的缺口，但通知停止的根因尚未确认，详见[通知中断与退出诊断](轻触通知中断与退出诊断.md)。长按研究留待后续。睡眠前关闭监听、唤醒后重新连接由应用负责，参见[微软事件监听说明](https://learn.microsoft.com/en-us/windows/win32/api/winbio/nf-winbio-winbioregistereventmonitor)。
