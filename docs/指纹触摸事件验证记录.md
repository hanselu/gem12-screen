# GEM12 指纹传感器触摸事件验证

日期：2026-10-09。

## 结论

本机内置 Microarray 指纹传感器可以通过现有 Windows 生物识别框架产生不识别身份的输入事件。本次用户确认完成 3 次轻触，探针收到 3 个目标设备事件，均返回成功状态。120 秒监听窗口内未收到其他事件。

这完成了“单次轻触能否作为面板切换输入”的第一步可行性验证。本次验证时尚未加入正式输入接口；后续已新增并验收独立的 `gem12_touch`，详见[独立轻触接口验证记录](独立轻触接口验证记录.md)。面板切换和长按判断尚未加入，也未验证大量连续操作、长期运行、睡眠唤醒或与 Windows Hello 的同时使用。

## 设备及接口

- 本机设备：Microarray WBDI，USB VID/PID `3274:8012`。
- 当前安装驱动：Microarray，版本 `9.47.11.214`；没有替换或修改驱动。
- Windows 生物识别枚举结果：目标设备 Unit ID 为 3，系统池（Pool 1），触摸式传感器（Subtype 2），能力标志 `0x00000007`。
- 使用 `WinBioOpenSession` 的系统池及默认配置，注册 `WINBIO_EVENT_FP_UNCLAIMED` 事件。
- 未注册 `WINBIO_EVENT_FP_UNCLAIMED_IDENTIFY`，未调用身份识别、指纹录入、模板读取或原始指纹采样接口。记录仅包含设备元信息和事件状态。
- 临时探针使用 Python ctypes 调用 Windows 自带 `winbio.dll`，参数类型和常量对照本机 Windows SDK `10.0.26100.0` 核对。
- 回调仅记录事件时间、设备编号和状态，将消息放入队列，并释放系统分配的事件内存；没有在回调中绘图或发送屏幕数据。

## 验证过程

1. 测试前确认 `WbioSrvc` 为 Stopped、启动类型为 Automatic。
2. 系统成功枚举目标设备、打开会话并注册事件监听，三个步骤 HRESULT 均为 `0x00000000`。
3. 监听准备好后，提示用户轻触 3 次，每次放开手指并间隔约 2 秒。用户确认操作已完成。
4. 探针收到以下事件；时间为相对探针启动的秒数，不是触摸响应延迟。

| 次数 | 相对时间 | 事件类型 | Unit ID | 操作状态 | RejectDetail |
|---|---:|---|---:|---|---:|
| 1 | 28.026 秒 | `0x00000001` | 3 | `0x00000000` | 0 |
| 2 | 30.989 秒 | `0x00000001` | 3 | `0x00000000` | 0 |
| 3 | 34.238 秒 | `0x00000001` | 3 | `0x00000000` | 0 |

5. 监听窗口结束，总运行时间约 120.196 秒，收到事件总数为 3。剩余静默期间没有额外事件；本次结果不等于已验证所有触摸操作都会严格产生一个事件。
6. 注销事件监听和关闭会话均成功，HRESULT 均为 `0x00000000`。

原始结果见[指纹触摸事件验证数据.json](指纹触摸事件验证数据.json)。

## 服务状态和清理

调用系统生物识别接口时，Windows 自动启动了 `WbioSrvc`。监听结束后，该服务仍为 Running，启动类型仍为 Automatic。

普通进程没有停止系统服务的权限。用户明确允许一次管理员确认后，仅停止了 `WbioSrvc`；已核对测试后状态恢复为 Stopped，启动类型保留 Automatic。没有修改指纹配置或服务启动配置。

临时探针和中间文件已在保存记录后清理。正式屏控代码未修改，屏幕未被操作。

## 对后续实现的意义

后续已基于此次验证增加独立的 Windows 输入监听模块 `gem12_touch`，由事件队列向调用方传递通知。显示及面板切换由调用方在回调之外处理，避免屏幕传输阻塞系统回调。新接口的真机验收也记录了一轮 3 次轻触仅收到 2 个事件的情况，不能据此保证所有操作都会逐次上报，详见[独立轻触接口验证记录](独立轻触接口验证记录.md)。

本次事件包含设备编号和采样状态，没有按下／松开状态或接触时长，不能据此直接实现参考项目的 400 毫秒长按。后续已完成[轻触与长按对照验证](指纹长按验证记录.md)：轻触 3 次收到 3 个事件，长按 3 次只收到 1 个同类型事件，当前 Windows 事件路径无法可靠区分两种操作。
